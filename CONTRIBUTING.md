# Contributing to Parallax

Thanks for taking the time to contribute. Parallax is a themed component library and demo
gallery built on [shadcn-svelte](https://shadcn-svelte.com/docs) — Svelte 5, Vite,
Tailwind CSS v4, [Bits UI](https://bits-ui.com). This document tells you how the repository
works and what a good change looks like here.

## Getting started

Requires Node.js 20.19 or newer (22.12+ on the 22 line) — Vite 8's own floor.

```bash
npm install
npm run dev              # http://localhost:5173 — hot reload
```

Every page of the gallery is reachable from the sidebar; the hash router means a plain static
server is enough — there is no backend.

## The quality gates

CI runs exactly these, and they all must pass before a merge:

```bash
npm run format:check     # prettier — the only formatting authority
npm run check            # svelte-check + tsc, 0 errors expected
npm run build            # the production build must succeed
npm run themes:audit     # contrast, brand/status separation, CVD simulation
npm run loaders:check    # loader CSS-in-markup styles svelte-check cannot see
```

Run them locally before opening a pull request. `npm run format` fixes formatting in place.

## Know which tier you are editing

Everything under `src/lib/components/ui/` belongs to one of two tiers, and the rules differ
— [`docs/CONVENTIONS.md`](./docs/CONVENTIONS.md) is the normative reference:

- **Registry components** (generated by the shadcn-svelte CLI) deliberately stay close to
  upstream so re-running the CLI produces a reviewable diff. Do not restyle or refactor them;
  the theme reaches them only through the tokens in `src/app.css`. If you must diverge from
  upstream to fix a real bug, say why in a comment at the divergence.
- **House components** are first-class code maintained here. Full-depth changes are welcome,
  provided they follow the house conventions (naming, variants, status vocabulary, imports,
  the `$bindable`/`onXChange` pairing).

## Generated files are never edited by hand

`src/themes.css` and `src/lib/themes/palettes.ts` are written by the theme generator. To change
a palette, edit `tools/themes/` and run:

```bash
npm run themes:generate  # rewrites the generated files, byte-identical per input
npm run themes:audit     # must stay clean — CI runs it too
```

A pull request that hand-edits a generated file will be asked to move the change into the
generator.

## Adding a component

Adding a component to the catalog is three compiler-linked edits:

1. a page under `src/lib/components/pages/`,
2. a line in `CATEGORIES` in `src/lib/hooks/route.svelte.ts` (the ladder — a component belongs
   to the first group whose admission test it passes),
3. its dynamic import in `src/App.svelte`.

Never write a route down anywhere else — routes, route types and the sidebar menu are all
derived from `CATEGORIES`. Every component must be rendered by at least one page.

## Commits and branches

- Branch names: `feat/<topic>`, `fix/<topic>`, `docs/<topic>`, `refactor/<topic>`.
- Commit subjects: `<type>: <imperative summary>` — e.g. `fix: retire the 28px off-ramp step`.
  Types in use: `feat`, `fix`, `docs`, `refactor`, `chore`.
- One intent per commit; the subject states the intent, the body (when needed) states the
  reasoning.

## Pull requests

- Keep them focused — one intent per PR.
- For anything visual, include screenshots in **both light and dark mode**; if a change could
  interact with palettes, check at least one non-default theme (the header's theme picker
  switches them live).
- State which tier the change touches (registry / house / pages / tools / docs) — it decides
  how the review reads it.
- The PR template's checklist mirrors the CI gates; tick it honestly.

## Writing style

All code, comments, documentation, commit messages and identifiers are written in English.
Comments carry reasoning, not narration: state the constraint the code cannot show, and cite
only what a reader can actually open (a file in this repository, or the published documentation
of a real dependency).

## Odd files, explained

- `skills-lock.json` pins the shadcn-svelte skill that AI-assisted tooling reinstalls into the
  gitignored `.claude/skills/`; it is harmless if you never use that tooling.
- `src/themes.css` and `src/lib/themes/palettes.ts` are generated — see above.
- `package.json` keeps every package in `devDependencies` on purpose: this repository is an
  application consumed as a git repo, never as an npm package, so everything is build-time
  input and one list is simpler than an arbitrary split. The single `overrides` entry
  (`@dnd-kit/geometry`) is load-bearing: it forces `@dnd-kit-svelte/svelte`'s declared
  `^0.1.21` up to the 0.2.x line the rest of the dnd stack uses, so drag objects never cross
  between two incompatible geometry copies.

## Questions and bugs

Open an issue with the matching template. For security concerns, do **not** open a public
issue — see [`SECURITY.md`](./SECURITY.md).
